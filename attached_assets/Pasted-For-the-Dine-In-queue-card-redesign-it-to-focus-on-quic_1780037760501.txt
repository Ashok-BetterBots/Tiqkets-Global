For the Dine-In queue card, redesign it to focus on quick decision-making rather than displaying every field as plain text. The booking ID (T003) should be the most prominent element on the left in a bold badge, while the customer name should appear beside it with a cleaner layout. Directly below the name, display the most important operational information as visual chips with icons instead of text lines. For example, show Party Size with a people icon and the number in bold (👥 5), Waiting Time or Join Time with a clock icon, Gender Preference with a gender icon, and Table Sharing Preference with a table/group icon. These key details should be displayed in a single compact row or two neat rows using icon-based badges, making them instantly scannable. The Party Size should be visually emphasized because it is the most critical factor when allocating tables. Remove duplicate or unnecessary fields such as both “partySize” and “Member Count” if they represent the same information. Technical or internal fields like “__fullName” should never be shown to users.

The card should follow a clear information hierarchy: Booking ID and Customer Name first, key seating requirements second, and actions last. Replace long text sentences such as “Share table with other guests: Yes” and “Split table and seat if crowded: No” with simple icon-based status chips that use a subtle color and a clear visual indicator (e.g., Shared Table Allowed, Split Seating Allowed). Keep secondary information lighter and less prominent. The “Allocate Table” button should remain large and visible but feel more premium with better spacing and a cleaner card layout. Add a small chevron or “More” button on the card header. Only the default Dine-In fields should be visible initially, while any additional custom fields added by a restaurant should remain hidden and appear only when the user taps the More/Expand button. The overall card should feel compact, modern, and operationally efficient, allowing staff to understand a guest’s seating requirements within 2–3 seconds without reading multiple text lines.
